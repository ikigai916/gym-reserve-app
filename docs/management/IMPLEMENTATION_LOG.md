# 実装ログ (IMPLEMENTATION LOG)

## 2025-12-28: Cloud Run 起動エラーの再修正（Firestore遅延初期化と環境変数対応）

### 変更の背景
- 前回の修正後も、Cloud Run でコンテナが 8080 ポートでリッスンを開始できずに起動失敗するエラーが継続。
- アプリケーション起動時のインポートフェーズで Firestore クライアントの初期化に失敗し、プロセスがクラッシュしている可能性が高い。

### 主要な変更点
1. **Firestore クライアントの遅延初期化 (Issue #31 関連)**:
   - `app/core/database.py` において、モジュール読み込み時の即時初期化を廃止。
   - `FirestoreProxy` クラスを導入し、実際にデータベース操作が必要になったタイミングで初めて `firestore.Client()` を呼ぶように変更。
   - これにより、Firestore 接続に問題がある場合でもサーバー自体は起動し、Cloud Run のヘルスチェックを通過できるようになる。
2. **Dockerfile の改善**:
   - `CMD` 命令を `sh -c` 経由に変更し、Cloud Run から渡される `$PORT` 環境変数を使用するように修正。
   - `PYTHONPATH` 環境変数を明示的に設定し、モジュールのインポートを確実に。
3. **詳細なロギング**:
   - `app/main.py` および `app/core/database.py` に起動時ログを追加し、失敗箇所を特定しやすくした。

### 技術的決定
- サーバー起動時の外部依存関係（Firestore）への即時接続を避ける「遅延初期化（Lazy Initialization）」を採用し、システムの耐障害性と起動速度を向上。
- インフラ（Cloud Run）のベストプラクティスに基づき、動的なポート割り当てに対応。
